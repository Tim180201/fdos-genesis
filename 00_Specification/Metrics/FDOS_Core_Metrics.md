# FDOS Core Metrics

Status: Released  
Version: 3.6

## Purpose

Define a small set of metrics that measure whether FDOS improves software delivery and organizational learning.

FDOS must not become KPI-heavy.
Metrics exist to support learning, not bureaucracy.

## Core Metrics

### Validated Learnings
Number of learnings that passed review and became validated knowledge.

Purpose:
Measures whether projects improve organizational knowledge.

### Knowledge Reuse Rate
Percentage of project decisions, patterns or templates reused from existing knowledge.

Purpose:
Measures whether knowledge actually helps future work.

### Lead Time
Time from approved work item to validated result.

Purpose:
Measures delivery flow without reducing quality.

### Quality Escape Rate
Number of defects or issues discovered after quality gates or release.

Purpose:
Measures whether quality processes prevent problems.

### Evidence Coverage
Percentage of standards, patterns or capabilities backed by documented evidence.

Purpose:
Measures whether FDOS remains evidence-based.

### Capability Maturity
Current maturity of active capabilities.

Purpose:
Measures whether organizational capabilities improve over time.

## Rejected Metrics

The following metrics are not core FDOS metrics:

- raw number of documents
- raw number of tasks
- raw number of meetings
- raw number of AI prompts
- individual productivity scores

Reason:
These metrics can create false incentives and do not directly prove better software delivery.

## Rule

A metric is only useful if it helps answer:

Does this improve the organization's ability to deliver better software faster and more reliably?
