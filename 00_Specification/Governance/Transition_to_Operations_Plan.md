# Transition to Operations Plan

Status: Released  
Version: 3.8 LTS

## Purpose

Define the transition from architecture development to operational validation.

## Operating Mode After v3.8 LTS

FDOS development shifts from:

Architecture Creation
→ Architecture Stabilization
→ Operational Validation

## New Development Flow

Real Project
→ Observation
→ Evidence
→ Learning
→ Knowledge Review
→ Organizational Memory
→ Targeted FDOS Revision

## Priorities

1. Operate frogs. productively.
2. Validate ADO through frogs.
3. Develop TimeTap using FDOS and ADO.
4. Capture evidence from real work.
5. Promote validated learnings into Organizational Memory.
6. Revise FDOS only when evidence demonstrates need.

## Explicit Non-Priorities

- new Core architecture
- new main folders
- speculative Business Architecture
- additional Core Capabilities
- Platform Runtime before project validation
- AI expansion without ADO evidence

## Success Criteria

The transition succeeds when:

- at least one real project is mapped to ADO
- project evidence is captured
- learnings are reviewed
- at least one FDOS improvement is justified by real evidence
- unnecessary architecture growth is avoided

## Guiding Sentence

The architecture serves projects.

Projects do not serve the architecture.
