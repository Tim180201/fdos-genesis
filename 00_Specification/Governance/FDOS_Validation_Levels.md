# FDOS Validation Levels

Status: Released  
Version: 3.8 LTS

## Purpose

Define how FDOS concepts, learnings, patterns, standards and capabilities mature through evidence.

## Validation Levels

### Level 0 — Concept

A proposed idea or architectural hypothesis.

Criteria:
- clearly described
- no practical validation required
- must not be treated as standard

### Level 1 — Experimental

A concept being tried in a controlled context.

Criteria:
- limited scope
- explicit owner
- expected evidence defined
- risks known

### Level 2 — Validated by Single Project

A concept has demonstrated usefulness in one real project.

Criteria:
- project evidence exists
- result is documented
- limitations are known
- review completed

### Level 3 — Validated by Multiple Projects

A concept has demonstrated usefulness across multiple independent contexts.

Criteria:
- evidence from more than one project or sufficiently distinct usage context
- reusable beyond original project
- risks and tradeoffs documented
- knowledge owner review completed

### Level 4 — Core Standard

A concept is stable enough to become part of the FDOS Core or official standard library.

Criteria:
- strong evidence
- repeated usefulness
- governance approval
- owner assigned
- lifecycle defined
- impact understood
- ADR recorded where architecture is affected

## Rule

No concept may skip validation levels unless the Architecture Board documents an explicit exception.

## Important Note

FDOS does not count projects mechanically.

Evidence quality matters more than project count.
