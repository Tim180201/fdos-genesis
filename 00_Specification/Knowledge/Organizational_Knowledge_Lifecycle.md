# Organizational Knowledge Lifecycle

Status: Released  
Version: 3.6

## Purpose

Define how experience becomes reusable organizational knowledge without promoting every observation into a standard.

## Lifecycle

Experience
→ Observation
→ Candidate Learning
→ Validated Learning
→ Knowledge
→ Classification
→ Pattern / Anti Pattern / Guideline / Decision
→ Standard Candidate
→ Standard
→ Capability / Reference Implementation Improvement
→ Project Usage
→ Experience

## Stages

### Experience
Something happens in real work.

### Observation
A relevant event, success, failure or deviation is recorded.

### Candidate Learning
A possible lesson is formulated.

### Validated Learning
The learning is reviewed and supported by evidence.

### Knowledge
The learning becomes reusable organizational understanding.

### Classification
Knowledge is classified into one or more outcomes:

- Pattern
- Anti Pattern
- Guideline
- Decision
- Standard Candidate

### Standard
Only repeatedly useful, reviewed and approved knowledge becomes a standard.

## Validation Criteria

A learning may become validated when:

- the source is known
- the observation is documented
- evidence exists
- impact is described
- a responsible reviewer approves it

A pattern may become validated when:

- it solves a recurring problem
- it is reusable outside the original case
- it has at least one practical validation
- risks and limitations are known

A standard may be approved when:

- it has validated evidence
- it improves software delivery
- it is understandable
- it is maintainable
- it does not create unjustified complexity

## Governance

Knowledge Owner: responsible for review quality.  
Capability Owner: responsible for capability impact.  
Architecture Board: responsible for standards and architectural consequences.
