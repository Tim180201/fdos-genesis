# Reality Before Architecture Principle

Status: Released  
Version: 3.6  
Classification: Constitutional Principle Candidate

## Principle

Reality has priority over Architecture.

FDOS does not define reality.
FDOS models reality through validated evidence.

## Meaning

The FDOS Specification represents the current best evidence-based understanding of how a learning software organization should operate.

When practical evidence contradicts the specification, the specification must be reviewed.

## Chain

Reality
→ Evidence
→ Knowledge
→ Specification
→ Reference Implementation
→ Project
→ Reality

## Rules

1. No architectural assumption becomes a standard without evidence.
2. Project reality may challenge any FDOS statement.
3. Evidence has higher authority than architectural preference.
4. Unsupported concepts remain experimental.
5. Stable standards require validated practical usefulness.

## Rationale

FDOS must not become theoretical overhead.
FDOS exists to help organizations improve software delivery through validated learning.
