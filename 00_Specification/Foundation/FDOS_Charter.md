# FDOS Charter

Status: Released  
Version: 3.7  
Classification: Foundational Charter

## Purpose

FDOS exists to improve the capability of software organizations to repeatedly deliver valuable, reliable and maintainable software through validated learning.

FDOS is not a documentation system.
FDOS is not a project management system.
FDOS is not a framework.

FDOS is the operating system of a learning software organization.

## Unchangeable Commitments

FDOS shall always follow these commitments:

1. Reality has priority over architecture.
2. Evidence has priority over assumptions.
3. Stability has priority over novelty.
4. Simplicity has priority over complexity.
5. Reuse has priority over reinvention.
6. Knowledge must be preserved.
7. Projects improve FDOS.
8. FDOS improves projects.
9. Architecture serves practice.
10. Human responsibility remains central; technology supports execution.

## What May Change

The following may evolve through validated evidence:

- Capabilities
- Workflows
- Reference Implementations
- Standards
- Metrics
- Knowledge structures
- Platform implementation

## What Must Not Change Lightly

The following may only change through constitutional governance:

- Purpose of FDOS
- Core principles
- Kernel structure
- Reality-before-Architecture principle
- Evidence-based evolution
- Separation of Specification, Reference Implementations and Projects

## Final Test

Every FDOS change must answer:

Does this help the organization deliver better software faster, more reliably, more maintainably and more reproducibly?

If the answer is not clearly yes, the change does not belong in the FDOS core.
