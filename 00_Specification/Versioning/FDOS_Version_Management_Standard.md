# FDOS Version Management Standard

Status: Released  
Version: 3.6

## Purpose

Ensure that every FDOS release remains traceable, reviewable and maintainable over time.

## Required Release Artifacts

Every FDOS release must include:

- README
- Release Notes
- Changelog
- Architecture impact summary
- Changed files
- Known risks
- Next recommended step

## Version Types

### Patch
Corrections, clarifications and non-structural improvements.

### Minor
New validated specifications, standards, reports or reference implementation updates.

### Major
Significant architecture phase transition or compatibility-impacting change.

### Baseline
A stable reference state used for validation.

### LTS
A long-term stable release with minimal change policy.

## Archiving

Old versions must not be deleted.

They should be archived as historical evidence of FDOS evolution.

## Changelog Rule

A changelog entry must describe:

- what changed
- why it changed
- what evidence or review justified it
- what impact is expected

## Release Principle

Versions document validated change, not creative activity.
